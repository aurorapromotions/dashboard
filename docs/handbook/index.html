2. How it's built

The dashboard is deliberately simple: plain web pages (HTML, CSS and JavaScript) with no build step, plus Google Firebase for logins and data.

Website filesHosted free on GitHub Pages, from the docs/ folder of the GitHub repository aurorapromotions/dashboard.
Sign-inFirebase Authentication: Google accounts, or email and password.
DatabaseFirebase Firestore (project sales-navigator-1b716, stored in Canada, northamerica-northeast2).
Security rulesFirestore rules decide who can read or change each record. They are the real lock; the pages only hide what the rules already forbid.
Connector (planned)A small free Cloudflare Worker to receive GoHighLevel leads, send approved emails and texts, and talk to Stripe/Square. Secret keys live there, never in the website.

3. Sign-in and access

Everyone signs in on the same screen, either with Google (for @aurorapromotions.ca or any Google/Gmail account) or with email and password (for any other email). Only people added on the Team & Access page get in.

RoleWhat they can do
Main adminihsan@aurorapromotions.ca. Always an admin; can't be removed or demoted.
AdminEvery tool with full access, plus Team & Access. Can add other admins.
Team leadA member with Full access to one or more tools, for example a sales lead who sees, edits and deletes all orders and changes Sales settings.
Member / repLimited access: only their own records (in Sales Navigator, orders where they are the sales rep). Can add and edit, cannot delete, cannot change settings.

Each person is stored in the database as members/<their email> with their name, role, whether they're active, how they sign in, and an access level per tool. The security rules read this record on every request.

A person's name is also their sales rep name. A rep with Limited access sees the orders whose Sales Rep exactly matches their name. Renaming someone on the Team page renames their orders too.

Password logins: when an admin adds someone with email and password, the app creates their login and Firebase emails them a link to set their own password. The admin never sees or types the password. The rules only accept that exact login (its hidden ID is saved on the person's record), so nobody can create a look-alike account.

4. Managing people

  1. Add someone: Team & Access → + Add person → name, email, how they sign in, role, and access for each tool → Add person.
  2. Change access: click Edit on their row, change the tool levels, save. It takes effect immediately.
  3. Remove someone: Edit → untick Can sign in. They're blocked right away; their records stay.
  4. Password problems: Edit → Send password email, or they can click "Forgot your password" on the sign-in screen.

5. Sales Navigator logic

Orders and invoice numbers

  • Each row is one product line. Lines that share the same Invoice # are one order. (Invoice #, PO # and order number are the same thing at Aurora, so only Invoice # is used.)
  • Order and client details (invoice #, status, rep, dates, client, payment platform, address) are the same for every line of an invoice; saving one line copies them to the others.
  • If you leave Invoice # blank, the app gives the next number automatically (INV-1035, INV-1036 …) from one shared counter, so two reps can never get the same number.

Money formulas

Base cost        = (Item cost + Running charge) × Items + Setup + Shipping + Other costs
Tax to supplier  = Base cost × Supplier tax %          (a real cost; never claimed back)
Total price      = Price per unit × Items + Customer tax  ("Total sales" includes customer tax)
Refund           = counted only when the status is Cancelled
Total cost       = Base cost + Tax to supplier + Refund
Gross profit     = Total price − Total cost             (before commission and platform fee)
Platform fee     = $ amount, or % of Total price        (default % only on card platforms)
Net profit       = Gross profit − Rep commission ($) − Platform fee − Customer tax

The customer tax is subtracted from net profit because it is paid over to the government (Settings → "Customer tax is paid over to the government").

What gets counted

  • Dashboard totals include every status except Quote and Cancelled (changeable in Settings → Counted in sales).
  • Days to deliver is counted once per order: from the order date to the delivery date of its last product, only when every product has a delivery date.
  • In-hands on time: an order is on time when every line was delivered on or before the in-hands date (or marked Yes/No by hand).
  • Customers: a client company is matched on its name (ignoring capitals and extra spaces); a contact person on their email, otherwise on name + company. A customer is "new" in the month or year of their first counted order, "repeat" after that.

Dropdown lists

Settings → Dropdown lists controls the choices for priority, status, acquisition channel, product category, decoration method, payment platform (and which ones charge the card fee) and shipping company. Renaming a choice updates the orders that use it. The Quote and Cancelled statuses can be renamed but not removed, because totals and refunds depend on them.

Import and export

Orders → Import CSV accepts a CSV saved from Google Sheets. Columns are matched by header name (old names like "Order #" or "PO #" are understood as Invoice #). Export CSV downloads every column, including the calculated ones.

6. Projects logic

At Aurora every project is a client order, so a project is linked to an Invoice # from Sales Navigator. Picking the invoice fills in the client company, contact, sales rep and in-hands date (used as the due date).

  • Project: name, invoice #, client, status (editable list in Projects → Settings; a status containing "Done" or "Cancel" counts as finished), priority, start and due dates, a project lead, the team, and notes.
  • Standard steps: a new project can start with the standard tasks (by default: artwork & proof approval, place order with supplier, production, shipping, delivered & in-hands confirmed), assigned to the lead. Edit the list in Projects → Settings.
  • Task: title, assigned person, due date, priority, status (To do → In progress → Review → Done), progress %, details and comments. Marking a task Done sets progress to 100%. A task is late when its due date has passed and it isn't done.
  • Views: My tasks (your tasks grouped into Late / This week / Later / No date, with a "New" mark on tasks assigned since your last visit), Board (drag cards between status columns), Projects (progress bar = done tasks ÷ all tasks).
AccessIn Projects they can…
Full (admins, project leads)See every project; create, edit and delete projects and tasks; assign anyone (assigning someone outside the team adds them to it); change Projects settings.
Limited (team members)See only projects they're on and their tasks; add tasks for themselves; change their own tasks (not reassign them); comment on any task in their projects. No deleting.

Behind the scenes each project and task stores its team (email addresses), and the security rules only let a Limited person read records whose team includes them. When a project's team changes, its tasks are updated to match.

From a project, Open invoice in Sales Navigator jumps to that invoice's product lines (for people with Sales Navigator access).

7. Making changes

The easy way: ask Claude

  1. Open the Claude desktop app → Code → start a session in the folder Desktop\Sales Navigator.
  2. Describe the change in plain words, e.g. "add a column for decoration colour" or "show profit by product category".
  3. Claude reads CLAUDE.md, makes the change, tests it, and uploads it. The website updates about a minute later. Your data isn't touched.

By hand (for a developer)

  1. Edit the files in docs/. There is no build step: what's in docs/ is exactly what the website serves.
  2. Test on this computer: run powershell -ExecutionPolicy Bypass -File tools\serve.ps1 -Port 8091, then open http://localhost:8091/docs/?demo=admin (or demo=lead, demo=rep). Demo mode uses fake people and browser storage, never the real database. Add ?seed=1 on the Sales page for example orders.
  3. If the change affects who may read or write data, edit firestore.rules and publish it in Firebase (Firestore → Rules → paste → Publish) before uploading the pages.
  4. Upload: commit and push to the main branch of aurorapromotions/dashboard (or drag the files into the repository on github.com). GitHub Pages republishes in about a minute.
  5. Update this Handbook if the logic changed.

Adding a new tool

  1. Create docs/<tool>/index.html (copy the top of an existing page, set window.PAGE={tool:"<key>",base:"../"}).
  2. Add it to TOOLS in docs/assets/core.js with ready:true. It then appears on the home page and Team page.
  3. Add a block for its data in firestore.rules using full('<key>') and limited('<key>'), and publish it.

8. Moving to aurorapromotions.ca

The data stays in Firebase whichever option you choose; only the address of the pages changes.

Option A (recommended): your own address, still hosted by GitHub

  1. Where the DNS for aurorapromotions.ca is managed (often your hosting control panel → Zone Editor / DNS), add a record: type CNAME, name dashboard, value aurorapromotions.github.io.
  2. On github.com → repository aurorapromotions/dashboard → Settings → Pages → Custom domain: dashboard.aurorapromotions.ca → Save. When the check passes, tick Enforce HTTPS.
  3. Firebase console → Authentication → Settings → Authorized domains → Add domain → dashboard.aurorapromotions.ca. (Without this, sign-in fails on the new address.)
  4. Open https://dashboard.aurorapromotions.ca and sign in. The old github.io address redirects there.

Option B: host the files on your own server

  1. In your hosting control panel, create the subdomain dashboard.aurorapromotions.ca (or use a folder such as aurorapromotions.ca/dashboard).
  2. Upload the contents of the docs/ folder (index.html, firebase-config.js, .nojekyll, and the folders assets, sales, team, handbook) into that subdomain's folder, keeping the folder structure. All links are relative, so a subfolder works too.
  3. Make sure the address has HTTPS (AutoSSL / Let's Encrypt in most control panels). Google sign-in requires it.
  4. Add the domain to Firebase → Authentication → Settings → Authorized domains.
  5. Optional: turn off GitHub Pages (repository → Settings → Pages → Source: None). Keep the GitHub repository as the master copy, and re-upload changed files to your server after each change.

9. Rebuilding from scratch

Use this if the project ever needs to be set up again under new accounts. You need a Google account (for Firebase) and a GitHub account (or your own hosting).

  1. Get the code: the GitHub repository aurorapromotions/dashboard, or the local copy on drive D: or the Desktop.
  2. Create a Firebase project at console.firebase.google.com (Google Analytics off).
  3. Database: Build → Firestore Database → Create database → production mode → a location near you.
  4. Sign-in: Build → Authentication → Get started → enable Google (set the public-facing name and support email) and Email/Password. Under Settings → Authorized domains, add the address where the site will live.
  5. Connect the site: Project settings → Your apps → Web (</>) → register → copy the firebaseConfig values into docs/firebase-config.js.
  6. Security rules: Firestore → Rules → paste the contents of firestore.rules → Publish. If the main admin is someone else, replace ihsan@aurorapromotions.ca in the rules and in OWNER at the top of docs/assets/core.js.
  7. Host the site: new GitHub repository → upload everything → Settings → Pages → Branch main, folder /docs. Or follow Option B above.
  8. First sign-in: the main admin signs in with Google; their admin record is created automatically. Then add the team on Team & Access.
  9. Bring data across: in the old dashboard, Sales Navigator → Orders → Export CSV; in the new one, Import CSV. Re-enter Settings (tax and fee defaults, dropdown lists) and people by hand.

10. Backups and copies

  • Code: online in GitHub (aurorapromotions/dashboard, with every past version), the working copy in Desktop\Sales Navigator, and a backup copy on drive D: (D:\Aurora Promotions Dashboard\Project). To refresh it, double-click Update this copy from GitHub.bat in D:\Aurora Promotions Dashboard.
  • Data: lives in Firebase. Download a copy regularly with Sales Navigator → Orders → Export CSV and save it in D:Aurora Promotions DashboardData backups. Firebase's own automatic exports need the paid Blaze plan.

11. Costs and limits

  • GitHub Pages: free. The repository is public, so the code can be seen by anyone; your data is not in it.
  • Firebase (Spark, free plan): about 1 GB of data, 50,000 reads and 20,000 writes per day, unlimited Google/email logins. Far more than a small team uses. If you ever outgrow it, the Blaze plan charges only for use above these amounts.
  • Planned extras: GoHighLevel email/SMS charges (your GHL plan), Stripe or Square card fees when clients pay invoices, Claude-written drafts (pay per use, a few cents each).
Never put secret keys in docs/. Stripe, Square, GoHighLevel or Anthropic keys must go only into the connector service (planned), never into the website files, because those are public.
